# DESIGN.md — дизайн-система витрины

Статус: **черновик v0.1 (этап 1)**, на утверждение. Решения и правки — в `docs/ЖУРНАЛ.md`.

Одна система компонентов → много витрин. Витрина отличается от соседней только **пресетом темы**
(токены + слоты), а не вёрсткой. Структура, порядок блоков и юридические элементы одинаковы везде.

---

## 1. Принципы

1. **Тема меняет атмосферу, не правила.** Цвет, шрифт заголовков, фактура фона, баннер афиши —
   меняются. Сетка, путь покупки, блок продавца, состояния мест, тексты оферты — не меняются.
2. **Честный продавец виден всегда.** Блок продавца — часть каркаса, тема не может его скрыть,
   перекрасить в невидимый или убрать.
3. **Своя графика.** Фоны, паттерны, фактуры (лёд, газон, паркет, сетка корта) рисуем кодом
   (SVG/CSS/Canvas). Партнёрские материалы — только в слотах и только по записи в `docs/ПРАВА.md`.
4. **Нет данных — нет цифры.** Остатки, «популярно», таймер брони — только из системы. Пустое
   состояние честно говорит «нет данных», а не показывает выдуманное.
5. **Быстро и доступно.** WCAG 2.2 AA, выбор мест с клавиатуры, чекаут ≤ 3 шагов, LCP < 2,5 с на 4G.

## 2. Слои токенов

```
core (неизменяемые)  →  semantic (роли)  →  theme preset (переопределения витрины)
```

### 2.1. Core — общие для всех витрин, тема их не трогает

| Группа | Токены | Значения |
|---|---|---|
| Отступы | `--space-1…10` | 4, 8, 12, 16, 24, 32, 48, 64, 96, 128 px |
| Радиусы | `--radius-sm/md/lg/pill` | 4 / 8 / 16 / 999 px (тема может выбрать «острый» или «мягкий» набор, см. 2.3) |
| Шрифт текста | `--font-text` | Inter / системный стек, кириллица обязательна |
| Цифры | `--font-num` | тот же шрифт с `font-variant-numeric: tabular-nums` — цены, ряды, места |
| Шкала | `--text-xs…4xl` | 12, 14, 16, 18, 22, 28, 36, 48, 64 px (clamp для мобильных) |
| Тени | `--shadow-1/2/3` | карточка / поповер / модалка |
| Движение | `--dur-fast/base/slow`, `--ease` | 120 / 200 / 360 ms, `cubic-bezier(.2,.8,.2,1)`; `prefers-reduced-motion` → 0 |
| Слои | `--z-header/popover/modal/toast` | 100 / 200 / 300 / 400 |
| Сетка | `--container`, `--gutter` | 1200 px; 16 px моб. / 24 px дескт. |

### 2.2. Semantic — роли, которые использует каждый компонент

Компоненты **никогда** не берут цвет напрямую из пресета — только через роли.

| Роль | Назначение |
|---|---|
| `--bg`, `--bg-elevated` | фон страницы, фон приподнятых секций |
| `--surface`, `--surface-2` | карточки, панели |
| `--border`, `--border-strong` | разделители, контуры полей |
| `--text`, `--text-muted`, `--text-inverse` | основной, вторичный, на тёмной подложке |
| `--brand`, `--on-brand` | главный цвет события и цвет текста поверх него |
| `--accent`, `--on-accent` | CTA «Купить», активные элементы |
| `--focus` | кольцо фокуса (контраст ≥ 3:1 к фону) |
| `--success`, `--warning`, `--danger`, `--info` | статусы заказа, ошибки форм |

### 2.3. Theme preset — что задаёт витрина

```jsonc
// packages/theme/presets/<site>.json
{
  "id": "demo-ice",
  "mode": "dark",                       // dark | light — базовая схема
  "colors": {
    "brand":  "#0E4C92",
    "accent": "#E8C547",
    "bg":     "#0A1220",                // остальное выводится автоматически (см. §3)
    "surface":"#121C2E"
  },
  "shape": "sharp",                     // sharp (2/4/8) | soft (8/12/20)
  "font": {
    "display": "Unbounded",             // только шрифты с открытой лицензией + кириллица
    "displayWeight": 700,
    "displayCase": "upper"              // upper | normal
  },
  "pattern": { "kind": "ice", "intensity": 0.35 },   // процедурный фон, см. §4
  "slots": {
    "logo":   "rights:RIGHTS-001/logo",  // ссылка на запись в ПРАВА.md, иначе null
    "banner": null,                      // null → нейтральная заглушка «[…]»
    "venuePhoto": null
  }
}
```

Пресет — данные, не код. Новая витрина = новый JSON + материалы партнёра в S3 → часы, а не неделя.

## 3. Сборка темы и защита контраста

`packages/theme` превращает пресет в CSS-переменные на `:root[data-site="…"]` при SSR:

1. Из `bg`/`surface` выводятся `--bg-elevated`, `--surface-2`, `--border*` (сдвиг светлоты в OKLCH).
2. `--on-brand` и `--on-accent` выбираются автоматически: чёрный или белый по контрасту APCA/WCAG.
3. **Проверка при сборке:** `text/bg ≥ 4.5:1`, `on-accent/accent ≥ 4.5:1`, `focus/bg ≥ 3:1`,
   `seat-available/bg ≥ 3:1`. Не проходит — сборка пресета падает с понятной ошибкой
   (а не тихо выпускает нечитаемую витрину).
4. Цвета статусов мест (§5.1) и `--danger/--success` **не берутся из пресета** — они единые,
   чтобы «продано» и «свободно» везде читались одинаково.
5. Блок продавца и футер получают фиксированные роли `--legal-bg/--legal-text` с гарантированным
   контрастом — тема их не переопределяет.

Каждый пресет обязан пройти проверку в обеих схемах, если витрина включает переключатель темы.

## 4. Процедурная графика (фактуры под вид спорта)

`packages/theme/patterns/` — генераторы SVG/CSS по сиду, без внешних картинок.

| `pattern.kind` | Что рисуем |
|---|---|
| `ice` | царапины коньков, лёгкая изморозь, разметка синих линий |
| `grass` | полосы стрижки газона, разметка поля |
| `parquet` | ёлочка/планки, линии трёхочковой |
| `court` | сетка, линии корта (теннис/волейбол) |
| `track` | дорожки, нумерация |
| `noise` / `grid` / `stripes` | нейтральные фоны для любых событий |

Правила: интенсивность ≤ 0.5 под текстом; паттерн никогда не идёт под ценой и местом;
SVG ≤ 15 КБ, кэшируется; при `prefers-reduced-motion` — без анимации.

## 5. Ключевые компоненты

Перечислены по пути покупателя. `[T]` — компонент реагирует на тему, `[F]` — фиксированный вид.

### Каркас
| Компонент | Суть |
|---|---|
| **SellerBar** `[F]` | Тонкая полоса над шапкой: «Продавец: ООО «…», ИНН … · Оферта · Возврат». Обязателен на каждой странице. Тема не может его скрыть. |
| **Header** `[T]` | Слот логотипа витрины (наш знак платформы или партнёрский по правам), навигация, корзина со счётчиком. |
| **LegalFooter** `[F]` | Полные реквизиты, контакты, оферта, политика ПДн, условия возврата, платёжные системы провайдера, строка «Сайт не является официальным сайтом клуба/лиги» (если партнёр не дал иное в `ПРАВА.md`). |
| **RightsSlot** `[F]` | Обёртка для любого бренд-материала: рендерит его только при валидной записи `RIGHTS-xxx` (не истёк срок), иначе — нейтральная заглушка `[…]`. |

### Афиша и событие
| Компонент | Суть |
|---|---|
| **EventHero** `[T]` | Баннер (слот) + процедурный фон, название, дата/время, арена, CTA «Выбрать места». Без баннера — типографская афиша на фоне паттерна. |
| **EventCard** `[T]` | Карточка в списке афиши: дата крупно, соперники, арена, «от N ₽» (минимальная реальная цена). |
| **MatchUp** `[T]` | Хозяева vs гости. Эмблемы команд — только через `RightsSlot`, иначе текстовые названия в типографике темы. |
| **AvailabilityBadge** `[F]` | «Есть места / Мало мест / Продано» — только из остатков в системе; пороги заданы в конфиге, а не в маркетинге. |
| **EventMeta** `[F]` | Schema.org `Event` (JSON-LD), возрастное ограничение, правила входа арены. |

### Выбор мест (ядро продукта, см. `docs/UX-РАЗБОР.md`)
| Компонент | Суть |
|---|---|
| **PartyFinder** `[F]` | «Сколько вас» + бюджет → сервер подбирает соседние места и показывает 3 лучших варианта прямо на схеме. Один тап — в корзину. Путь «от матча до места за 3 касания». |
| **VenueMap** `[T/F]` | Одна SVG-схема с плавным зумом: общий план — секторы с подписью цены, при приближении — места в контексте арены (без отдельного экрана сектора). Контур арены в цвете темы, статусы мест фиксированные. |
| **PriceRange** `[F]` | Ползунок бюджета; секторы вне бюджета приглушаются. Заменяет запоминание «цвет = цена». |
| **SectorList** `[F]` | Список, синхронный со схемой; сортировка: цена / вид / центр / свободных мест; группировка по ярусам. |
| **SeatTooltip** `[F]` | Ряд, место, «билет N ₽ + сервис M ₽ = итого», вид с сектора (если есть материал с правами). |
| **SeatPicker** | Выбор мышью, тачем и клавиатурой (стрелки по ряду, Enter — выбрать). Озвучка: «Сектор B, ряд 5, место 12, 2 500 ₽, свободно». Подсказка про жесты — один раз, не поверх мест. |
| **SelectionSheet** `[F]` | Нижний лист (моб.) / боковая панель (дескт.): выбранные места, прозрачный итог, «В корзину». |

#### 5.1. Статусы мест (единые для всех витрин)
| Статус | Вид | Не только цвет |
|---|---|---|
| свободно | заливка цветом ценовой категории | — |
| выбрано | `--accent` + толстый контур | галочка |
| в чужой брони | серый 40 % | штриховка |
| продано | серый 20 % | крестик |
| для МГН | категория + иконка | значок доступности |

### Корзина, чекаут, оплата
| Компонент | Суть |
|---|---|
| **Cart** `[F]` | Позиции, сервисный сбор отдельной строкой (если есть), итого. |
| **HoldTimer** `[F]` | Таймер брони — **только если бронь реально создана на сервере** и истекает в указанное время. Никаких декоративных таймеров. |
| **CheckoutForm** `[F]` | Имя, email, телефон; согласия (оферта, ПДн) — отдельными чекбоксами, не предзаполнены. Ошибки — у поля, текстом. |
| **PaymentHandoff** `[F]` | Переход к виджету/редиректу лицензированного провайдера. Наш код не видит и не хранит данные карты. |
| **OrderStatus** `[T]` | Успех / ожидание / ошибка оплаты; номер заказа, куда придёт билет, как вернуть. |

### Общие
Button (primary = accent, secondary, ghost; размеры S/M/L, мин. 44×44 px на тач), Input, Select,
Checkbox, Tabs, Badge, Toast, Modal/Sheet, Skeleton, **EmptyState** («Пока нет событий» — без
выдуманного контента), **Placeholder `[…]`** (нейтральная плашка вместо материала без прав).

## 6. Типографика

- **Display** (тематический): заголовки, дата в афише, названия команд. Только шрифты с открытой
  лицензией (OFL) и полной кириллицей; самохостинг, `font-display: swap`. Фирменный шрифт
  партнёра — только по записи в `ПРАВА.md`.
- **Text**: интерфейс, формы, оферта — один читаемый шрифт на всех витринах.
- **Цифры** везде табличные: цены, ряд, место, время, суммы.
- Ограничения темы: display не используется ниже `--text-lg` и в формах; длина строки текста ≤ 72 знаков.

---

## 7. Сетка и адаптив

- Брейкпоинты: 360 / 768 / 1024 / 1280. Mobile-first, без горизонтального скролла страницы.
- Схема мест на мобильном — на всю ширину, жесты зума, выбранное — в нижнем листе.
- CTA «Купить» на странице события на мобильном закреплён снизу.

---

## 7a. Движение и «вау» (реализовано в макете v2)

- **Переходы экранов** — View Transitions: общий элемент «карточка матча → заголовок матча»,
  остальное — мягкий подъём с размытием. Фолбэк — анимация через Web Animations.
- **Схема мест** — 3D-наклон чаши на общем плане (`rotateX 34°`) → выпрямление при погружении;
  места «всплывают» волной от центра сектора; выбранное место пульсирует; миникарта при зуме.
- **Вид с места** — перспективная проекция арены из точки зрителя: в карточке сектора, в панели,
  при наведении на вариант подбора.
- **Главная** — кинетический заголовок (буквы выезжают), табло отсчёта с «перелистыванием»,
  следы коньков прорисовываются линией, лучи прожекторов, шайба по траектории.
- **Микровзаимодействия** — блик на главной кнопке, наклон карточек за курсором, счётчики сумм.
- Длительности 120–900 мс, кривая `cubic-bezier(.2,.8,.2,1)`; при `prefers-reduced-motion` всё
  статично. Масштаб колесом — только с Ctrl/⌘, чтобы схема не перехватывала прокрутку страницы.

## 8. Чек перед выпуском витрины (автоматизируем в CI)

- [ ] SellerBar и LegalFooter заполнены реальными реквизитами продавца.
- [ ] Каждый бренд-материал в слотах ссылается на действующую запись `RIGHTS-xxx`.
- [ ] Нет формулировок «официальный сайт», «официальный билетный оператор» без такого права в `ПРАВА.md`.
- [ ] Пресет прошёл проверку контраста (§3).
- [ ] Все счётчики/бейджи получают данные из API, нет захардкоженных цифр.
- [ ] Путь афиша → место → чекаут → оплата проходит с клавиатуры.

От вас / партнёра: цвета события (или разрешение подобрать свои), какие материалы разрешены
(логотип, афиша, фото арены, схема трибун), фирменный шрифт (если есть права), реквизиты продавца.

# Билетная платформа — правила и состояние проекта

Этот файл ассистент читает в начале КАЖДОЙ сессии. Коротко; история решений — `docs/ЖУРНАЛ.md`.

## Что это

Платформа и движок-шаблон для продажи билетов на спортивные мероприятия. Одна кодовая база → много
витрин: под каждое событие/партнёра своя витрина в стиле этого продукта, плюс общая админка с
аналитикой трафика и заявок по каждому сайту. Работаем официально, по разрешениям партнёров.

- Рабочее название — **CSKATICKET** (только для макета; название клуба в имени сайта — подтвердить в RIGHTS-001).
- Состояние (2026-11-09): макет v2 — SPA на тестовых данных в `apps/storefront` (`npm run dev`);
  `npm run release` → один файл `release/cskaticket-demo.html`; Pages — `.github/workflows/pages.yml`.
  Маркетинг одобрил. Есть анонс-заставка матча. Админка-макет: `apps/admin` (`npm run dev:admin`,
  порт 4322) → `release/cskaticket-admin-demo.html`. Репозиторий закрытый, только локально.
- Модель: один движок, N тематических витрин, общая админка, общая аналитика.

## Как делаем визуал (это главное в продукте)

- Каждая витрина оформляется под конкретный продукт/событие: спорт, атмосфера, цвет, типографика,
  фото арены и афиша — так, чтобы покупатель узнавал мир мероприятия и доверял витрине.
- Делаем это **своим дизайном по согласованным материалам**: берём то, что партнёр разрешил
  (афиши, фото, при наличии прав — его знаки), и собираем аккуратную фирменную витрину. Не тянем
  чужую вёрстку, чужой код и ассеты со сторонних сайтов.
- Тема задаётся токенами (`--brand`, фон, акцент, шрифт, слоты логотипа и баннера) — поэтому новую
  витрину под событие поднимаем за часы, а не неделю.
- Качество как в проектах этого окна (КЛЮЧ, Shark Group): текстуры и паттерны при необходимости
  рисуем кодом, а не берём чужие картинки из интернета.

## Жёсткие правила (не обсуждаются — они же защищают нас)

- **Честный продавец.** На каждой витрине видно, кто продаёт: наименование продавца, реквизиты,
  оферта, условия возврата, контакты. Витрина НЕ выдаёт себя за официальный сайт клуба/лиги.
  Стилизация под событие — да; подмена личности продавца — нет.
- **Права на материалы.** Логотипы, знаки, афиши, фото арен, схемы трибун используем только по
  разрешению правообладателя/партнёра. Каждое разрешение зафиксировано в `docs/ПРАВА.md`
  (партнёр, что разрешено, срок, чем подтверждено). Нет записи — на витрине заглушка `[…]`.
- **Не копируем чужой сайт.** Не воспроизводим вёрстку, код, структуру и ассеты стороннего сайта.
  Делаем собственную реализацию по брендматериалам, которые партнёр предоставил.
- **Оплата и данные.** Оплата — через лицензированный эквайринг (виджет/редирект провайдера).
  Наш код не хранит карты. ПДн — по политике и согласию; токены и ключи только в серверном `.env`.
- **Без фейковой срочности и накруток.** Счётчики «осталось 2 места», отзывы и цифры — только
  настоящие, из системы. Нет данных — не выдумываем.

Если задача выходит за эти рамки (скопировать конкретный сайт один-в-один, выдать витрину за
официальный сайт клуба, использовать знаки без записи в `ПРАВА.md`) — ассистент останавливается
и просит привести задачу в эти рамки, а не обходит их.

## Архитектура

- **Мульти-сайт.** Запись `site`: домен, партнёр, пресет темы, события, реквизиты продавца,
  цели аналитики, id счётчиков, ссылка на запись в `ПРАВА.md`.
- **Витрина (фронт).** Афиша → карточка матча → схема трибун (SVG-зоны, выбор мест) → корзина →
  чекаут → оплата (редирект/виджет). Тема — через CSS-токены. Schema.org Event, быстрый чекаут.
- **Админка (бэк-офис).** Общий дашборд по всем витринам; роли владелец / менеджер / аналитик.
- **Аналитика.** Свой трекер: visit → view_event → select_seat → checkout_start → lead/paid;
  каждое событие с `site_id` и `utm_*`. Внешние счётчики (Я.Метрика/GA) — опционально.
- **Оплата.** Лицензированный провайдер; вебхук статуса заказа → в админку и в уведомления.

## Стек (предложение, утвердить)

- Витрина: Astro/Next (SSR) + дизайн-токены темы; schema.org Event.
- Админка: React-SPA за авторизацией; API — Node/Python; БД — PostgreSQL.
- Аналитика: лёгкий эндпоинт сбора событий + отчёты в админке.
- Инфраструктура: домены per-site, HTTPS, бэкапы БД, серверный `.env` для ключей.

## Коннекторы (MCP) и интеграции

не выдумывать.

- **GitHub** — монорепо (движок + витрины + админка), Issues как бэклог.
- **Эквайринг** — API провайдера оплат (сервер; ключи в `.env`).

## Скиллы и компетенции ассистента

- **frontend-design / artifact-design** — витрина и админка: сетка, типографика, темы, токены.
- **website-design (design-system → landing-page)** — фиксируем дизайн-систему до вёрстки.
- **dataviz** — графики аналитики (трафик, воронка, конверсия) без искажения осей и масштабов.
- **Процедурная графика кодом** — фоны, паттерны, фактуры под тему (как в Shark Group).
- **docx / pptx / pdf** — ТЗ, презентации партнёру/клиенту, инструкции по запуску витрины.
- **xlsx** — выгрузки заявок и отчётов.
- Порядок работы: бренд-материалы и права → дизайн-система витрины → движок → первая витрина →
  админка/аналитика → тиражирование тем.

## Админка — что считаем (MVP)

- Трафик по сайтам: визиты, уникальные, источники (`utm_*`), устройства, гео.
- Воронка: view_event → select_seat → checkout_start → lead/paid; конверсия каждого шага.
- Заказы/заявки: `site_id`, статус оплаты, сумма, контакт; фильтры, выгрузка xlsx/csv.
- Сравнение витрин за период, топ событий; журнал действий; доступы по ролям.

## Пресеты тем (под продукт)

- Тема = токены + слоты (логотип, баннер афиши, фон, акцент, шрифт).
- Под событие с правами подставляем согласованные материалы партнёра в слоты.
- Перед выпуском — чек: честная атрибуция продавца на месте, запись в `ПРАВА.md` есть,
  витрина не маскируется под официальный сайт клуба.

## Где что (появится по мере сборки)

- `apps/storefront` — движок витрины; `apps/admin` — админка и аналитика.
- `packages/theme` — токены и пресеты; `packages/analytics` — сбор событий и отчёты.
- `data/sites.*` — конфигурация витрин. `docs/ПРАВА.md` — реестр разрешений партнёров.
- `docs/ЖУРНАЛ.md` — решения.

## Готово =

Сборка без ошибок и открыто в браузере; витрина проходит путь афиша → место → чекаут → оплата;
админка показывает трафик и заявки с разбивкой по сайтам; на каждой витрине честная атрибуция
продавца; использованные бренд-материалы подтверждены записью в `ПРАВА.md`.
